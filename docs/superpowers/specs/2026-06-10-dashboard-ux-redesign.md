# Dashboard UX Redesign

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the manual Ingestar/Explorar buttons with a pipeline-first dashboard where the data flow is always visible and no action blocks the UI.

**Architecture:** A persistent pipeline bar shows the 6 stages of the data flow. Tabs align 1:1 with those stages. The sync runs automatically or on demand via a small header icon — no blocking actions anywhere.

**Tech Stack:** SvelteKit, Svelte components, existing worker API (`/health`, `/run-cron`, `/gap-radar`, etc.)

---

## Design Decisions

### Pipeline stages (left → right)

| Stage | Tab name | What you see |
|---|---|---|
| 1 | Señales | Raw collected signals from all collectors |
| 2 | Dolor | Friction analysis profiles (FrictionProfile per signal) |
| 3 | Segmentos | Discovered segments from latest automatic sync |
| 4 | Oportunidades | All scored segments — analysis only, no deploy action |
| 5 | Radar | Segments with real gap (pain high + no landing) — deploy here |
| 6 | Leads | Email captures after landing deployment |

### Header

- Remove the `▶ Ingestar` button entirely
- Add a sync status pill: `● hace 2h ↻`
  - Green dot = last sync successful
  - "hace Xh" = time since last sync
  - `↻` = click to force manual sync (fire and forget, no blocking feedback)
- Config tab removed — replaced by `⚙` icon button in the header (opens ConfigForm modal or existing tab rendered as overlay)

### Pipeline bar visual states — two colors only

| State | Circle | Bar | When |
|---|---|---|---|
| `done` | Violet filled, white ✓ | Violet | Stage completed in last sync |
| `running` | Violet filled, `···` pulsing | Violet 30% opacity, pulsing | Stage currently executing |
| `pending` | Light gray, ○ | Light gray | Not yet reached this sync |

No green, no amber, no red in the pipeline bar. Violet (`#7c3aed`) is the only active color.

Clicking any pipeline stage navigates to its corresponding tab.

### Oportunidades tab — analysis only

- Scored list ordered by score descending
- Each row: score badge | title | pain summary | status badge (watching/testing/scaling/killed) | signal count + mini bar
- **No "Desplegar →" button** — the user navigates to Radar to act

### Radar tab — decision and action

- Shows only opportunities where `gap_score > 0` and `has_landing = false` (or low gap from `GapEntry`)
- Ordered by `gap_score` descending
- Each row: gap score badge | title | pain + why gap exists | "Desplegar →" button
- Rows where a landing already exists: dimmed, button reads "Desplegado ✓" (disabled)
- **This is the only place with a deploy button**

### Segmentos tab — passive

- Grid of discovered segments from latest sync
- No "Descubrir ahora" / "Explorar" button — discovery is automatic (it's the "Segmentos" stage of the pipeline)
- Shows: profile name, pain, keywords, discovery score, income tier
- Shows timestamp of last discovery run

### Señales tab — new

- Table/list of raw signals, most recent first
- Columns: date, segment, source, title/text excerpt, signal strength
- Read-only

### Dolor tab — new

- List of friction profiles generated by the LLM analyzer
- Groups by segment
- Shows: problem type, intensity, frequency, pain summary, confidence
- Read-only

### Sync behavior

- Cron fires every 12h automatically — all 6 stages run in sequence
- `↻` in header: POST `/run-cron`, returns immediately, pill changes to `● sync en curso…` (pulsing dot)
- Pill updates to `● hace X min` when health endpoint shows collectors completed
- No 30-second forced delay — page polls `/health` every 5s until pipeline stages reflect completion, then reloads data via `invalidateAll()`
- **No blocking**: the user can navigate tabs freely during a sync

### Config

- Removed from tabs
- `⚙` icon in header opens the existing `ConfigForm` in a slide-over panel or modal
- No route change needed — can be a local `showConfig` boolean

## Component changes

### `+page.svelte` (dashboard)

- Remove: `ingestRunning`, `ingestError`, `ingestCollectors`, `pollTimer`, `allDone`, `runCron()` (the old complex polling logic)
- Remove: ingest-panel HTML block
- Remove: `runDiscovery()` function
- Add: `syncStatus` reactive state (`idle | running | done`) driven by simple `/health` poll
- Add: `showConfig` boolean toggling ConfigForm panel
- Replace: tab list from `['oportunidades','sectores','leads','config','radar']` to `['senales','dolor','segmentos','oportunidades','radar','leads']`
- Add: `PipelineBar` component

### New `PipelineBar.svelte` component

Props:
```ts
export let stages: Array<{
  key: string;       // 'senales' | 'dolor' | 'segmentos' | 'oportunidades' | 'radar' | 'leads'
  label: string;
  sub: string;       // e.g. "73 señales", "en curso", "—"
  state: 'done' | 'running' | 'pending';
}>;
export let activeTab: string;
export let onStageClick: (key: string) => void;
```

Renders the 6 circles + connectors + tabs row. Internal CSS handles the two-color state system.

### Pipeline state derivation (in `+page.svelte`)

Derive each stage's state from existing data:
- `senales`: `done` if `stats.total_signals > 0`, else `pending`
- `dolor`: `done` if any signal has `friction_analysis` set (need count from health or new stats field), else `pending`
- `segmentos`: `running` if sync in progress and not yet done; `done` if `discovery.candidates.length > 0`; else `pending`
- `oportunidades`: `done` if `opportunities.length > 0`, else `pending`
- `radar`: `done` if `gapRadar.length > 0`, else `pending`
- `leads`: `done` if `leads.total > 0`, else `pending`

### `OpportunityList.svelte` (rename or modify)

- Remove the "Desplegar →" button from each row
- Add mini signal-count bar visualization

### `GapRadar.svelte`

- "Desplegar →" button stays here (it's the sole deploy trigger)
- Deployed rows dimmed with "Desplegado ✓" disabled button
- Order rows by `gap_score` descending (already sorted by server)

### New `SignalsTable.svelte` component

- Simple table: date, segment, source, excerpt, signal_strength bar
- Fetched via existing `GET /signals` endpoint (needs to be added to page load or lazy-loaded)

### New `FrictionList.svelte` component

- Groups by segment, shows FrictionProfile fields
- Data sourced from signals that have `friction_analysis` set (filter client-side from signals data, or add `/pain-profiles` endpoint)

### `SectorsGrid.svelte`

- Remove "Descubrir ahora" button (currently in `+page.svelte` wrapping this component)
- Add last-discovery timestamp in the grid header

## API changes needed

### `GET /signals` — expose via page load

Currently exists in worker but not loaded in the page. Add to `+page.server.ts` load function:
```ts
workerFetch(`${base}/signals?limit=200`, env)
```

### Stats — add `analyzed_count`

Add `analyzed_count: number` to the stats response (signals with `friction_analysis IS NOT NULL`). Used to populate the "Dolor" stage sub-label.

## What is NOT changing

- Worker API routes — no backend changes needed except stats field
- Auth flow
- DeployModal component
- ConfigForm component (just moves to a modal/panel trigger)
- LeadsTable component
- All scoring, collection, discovery logic
